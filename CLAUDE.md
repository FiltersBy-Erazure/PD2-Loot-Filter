# Erazure PD2 Loot Filter: working rules

## What this repo is
- A Project Diablo 2 (PD2) loot filter, published to players through the PD2 launcher.
- **The source is `sections/*.filter`. Edit only those.** The 14 `.filter` files in the repo root are
  GENERATED by `tools/build.py`. Never edit them (a deny rule in `.claude/settings.json` blocks it).
- Longer background (section map, rule counts, roadmap, open questions): `HANDOFF.md`. Read it for big tasks.

## Build system
- `python tools/build.py` joins `sections/*.filter` in filename order into `Erazure-Main.filter`, fills
  `<<VERSION>>` (Horadric Cube section) from `version.json`, then writes the 7 toggle variants and the 6 style variants.
- `python tools/build.py --check` changes nothing and must print "All 14 filters in sync" before any commit.
- A PostToolUse hook runs the build after every Edit/Write to `sections/`, `version.json` or
  `filter_definitions.json`. If it reports an error, fix it. Edits made any other way (Bash, scripts)
  don't trigger it: run `python tools/build.py` yourself afterwards.
- The build fixes section-file format in place (CRLF, no BOM, final line break) and reports "Fixed ...".
  Files created with the Write tool come out LF, so expect that note for new sections.
- `build.bat` (the author double-clicks it) = `--stamp` (today's date into `version.json`) + build + check.
  **Never stamp or edit `version.json` unless the author asks.** The season name also lives there.
- The GitHub Action runs `--check` on every push.
- Style variant **Erazure - Minimal** (2026-10-19, in `filter_definitions.json`): `STYLE_VARIANTS` in
  `tools/build.py` builds `Erazure-Minimal.filter` = Main with the aliases of `styles/minimal.filter` (one
  `Alias[NAME]:...` line per alias that looks different; each replaces that alias's line in `sections/`, so the
  other filters never change). It has no toggle block of its own (Main's toggles). Since 2026-10-21 (the author) the
  same style file also makes **Erazure - Minimal - Revealed**, **- BIG GG** and **- PoE** from the matching Erazure
  toggle version (launcher keys 13-15, in that order after Minimal and before Corrlorized; the author's list: no
  combined versions such as Revealed - BIG GG). The style file still names all 8 toggle combinations on the Cube
  (`Big GG`, spelled as Erazure's and Corrlorized's Cube names), so a toggle block switched by hand names itself.
  Its looks can only differ through
  aliases: a symbol typed into a rule becomes an alias first (`RARE_JEWEL_NAME`, `MAGIC_JEWEL_NAME` in 040; the
  Horadric Cube's version names in 020, one per toggle combination: `MAIN_VERSION_NAME`, `REVEALED_VERSION_NAME`,
  `BIG_GG_POE_VERSION_NAME`...), with Main's text, so the other filters draw exactly what they did.
  2026-10-20, the author: also magic charms, rings and jewel arrows, normal-tier sets, the Rainbow Facet's name and
  the PD2 items' symbols (tokens, organs, sigils, Terror / Hatred / Void items, Craft Infusions), and these aliases
  pertain to Corrlorized too: where Corr restyled such symbols, `styles/corrlorized.edits` sets the alias's value
  (an `Alias[...]` `-`/`+` entry: the magic charms) and his rule entries keep only his other words.
  BH trims an alias's text (both ends): spaces at an alias's edge never show. `tools/style_map.py` writes the
  players' page of the differences (below). The author edits Main's aliases (040's symbol aliases and 020's
  version names) and Minimal's on one claude.ai page since 2026-10-22, the alias editor
  https://claude.ai/artifact/FkKQttkkkcUzqV7uL8PoS5: one card per alias with Main's and Minimal's text side by side,
  and whether Corrlorized follows Main there. `python tools/alias_editor.py` writes it (`tools/alias_editor.html`,
  gitignored, from `tools/alias_editor_template.html`); rebuild and republish it to that URL after an alias change.
  Its db (read it with ArtifactData): `aliases/main`, `edits` = alias -> Main's new text, and `styles/minimal`,
  `edits` = alias -> Minimal's own text, or null for no Minimal line (Minimal draws Main's look). When the author
  says to apply them: save them as `{"main": {...}, "minimal": {...}}`, run `python tools/alias_editor.py --apply
  FILE --dry-run`, then without `--dry-run` (it writes 040 / 020 and `styles/minimal.filter`, then runs the hook's
  generators and the build), rebuild and republish the page and clear the applied `edits`. The separate Minimal
  page https://claude.ai/artifact/FcQ2vqCdGs6jeL9ZqzahsD now only links to it.

  the minimap icons of Small and Grand Charms under item level 90 stay off, and since his v2 (2026-10-20) the Highest

  19 magic charm tags of 240 and 20 affix tags of 300 switched off (`x`), no icons or notifications for Flawless and
  Perfect gems in maps (Skulls keep theirs) nor for runes El to Fal (El to Io: only the icon codes go, so the rules
  still stop the display; switched off, the runes would fall through to later rules), and the ground disguises in
  his colors: `LIL GG` sage, `BIG GG` orange.
  An entry names its line by text (`@ <section>:<line>` is a hint the build keeps up to date): `-`/`+` changes what a
  rule shows, never its condition or comment (filtering stays the author's); `=`/`+` inserts lines after one; `x`
  switches one rule off; `*` every rule of the `@` section whose condition has those words (`!STAT360>0`: the rules
  of that section added later go too). Every build applies them to today's sections: a line by its
  text, else its condition and comment, else 80% alike nearby (what it shows at least 50% alike); the author's and
  the friend's word changes merge, his look winning where both changed the same words; then the build writes each
  entry back as its line is now (commit `styles/` and the two Corrlorized filters with the others). An entry that
  finds no line is left out and named on the build's "Style ..." line, which the hook passes back: tell the author
  (`python tools/style_edits.py corrlorized --report`; `--diff` lists every change). Edit the author's rules in
  `sections/` as always: Corrlorized follows. `explain_item.py --variant "Corrlorized - Main - PoE"`; CI runs
  `lint_filter.py --style "Corrlorized - Main - PoE"` (the lines the style wrote) and `style_edits.py --selftest`.
- `sections/045-unique-set-rolls.filter` is GENERATED by `tools/gen_unique_rolls.py` from
  `docs/pd2-unique-set-items.tsv` (PD2's own unique/set tables: stats, roll ranges, fingerprints), `docs/items/`
  (wiki: item names, roll text, and items the tables lack, e.g. Kadala's Heirloom, split per version) and
  `tools/unique_roll_picks.txt` (which rolls each item shows). Never edit it by hand: edit the picks file
  (remove `auto` from a line to keep your change) and the hook regenerates. The wiki is often wrong about how
  the game stores a stat (oskills are `OS<n>`, not `SK<n>`; chance-to-cast uses PD2's "Proc" skill IDs), so the
  game data wins. BH's `ED` reads +% defense on armor, so there a unique's +% damage roll is `edam` (`EDAM`,
  `ROLL_EDAM_TAG`) and `ed` is +% defense; on weapons and jewelry `ed` is +% damage. `DEF` is the item's total
  defense (Griffon's Eye: 195 for +145). The author's `PLUSDEF` (condition, `%PLUSDEF%`, formula `plusdef`: the
  defense from affixes, runeword and sockets, BH PR #105) shipped in the S14 beta BH.dll of 2026-10-19: the `def`
  roll tags of uniques and sets (300) and runewords (305, `GUARD_CODE` in its generator) compare and show it
  (`145def`); the rolls keep the code `DEF` in the TSVs and generators. S13's live BH.dll lacks the word.
  Each season and after a PD2 item patch: `python tools/pd2_data.py --extract "<Diablo II folder>"`
  (reads `ProjectD2\pd2data.mpq`; also refreshes `tools/pd2_stat_priority.tsv`), then regenerate and `--fix`.
  The author picks rolls in a page: `pick_rolls.bat` (double-click) = `python tools/gen_unique_rolls.py --picker`, which writes and opens
  `tools/roll_picker.html` (gitignored); it saves the picks file, and `build.bat` regenerates and builds.
  Its preview draws each label as the game does (tag formats read from `300-affix-tags`, BH's name cut, a
  D2-style font downloaded once into the gitignored `tools/.cache/`).
  Every variable roll is pickable; a pick of a roll with no tag line yet (`*` in the picks file) is a request:
  `--requests` lists them (add the 300 line + `COVER` slot) and the rolls with no known filter code
  (codes the author finds go in `AUTHOR_CODES`). Tag order: a later 300 line puts its tag further left, and the
  game lists stats by PD2's `descpriority` (`tools/pd2_stat_priority.tsv`). So `300-affix-tags` is one block per
  stat, lowest-listed first: put a new tag line anywhere and run `python tools/tag_order.py --fix` (lint flags a
  line out of place; a tag line's description is split off so description notes keep their order). Stats of
  equal priority come in an order that differs per item; the -res group tag follows each item's own order
  (`ERES_ORDER` in the generator, from in-game screenshots). One stat with several skills (classes, tabs, auras)
  lists the higher number first (Arm of King Leoric: Raise Skeleton Archer 89, Warrior 70, Skeleton Mastery 69),
  so a block's lines go from the lowest number to the highest (`--fix` sorts them; 310-staffmods' class runs too).
  Special picks: per-level rolls (`life/lvl`, `mf/lvl`) show per level, or the total at your level while worn
  (`EQUIPPED`); `randsk` / `randclsk` show the random skill / class an item got (Ormus' Robes, Spirit Keeper,
  Spirit Ward); `ver` names an item's version (`Strk`/`Cast`, `2msw`/`2msa`); `masteries` is `3/3/3` (cold,
  lightning, fire).
  Labels BH would cut (56 characters): `tools/unique_cut_rules.txt` (the author's review, 2026-10-19; named as in the
  picks file) lists an item's steps, taken in order and each only where the label is still cut: `drop <roll>`,
  `short <name>` (045 rebuilds the name as `%BASENAME%%NL%<short>` before every other rule; a name's lines are stored
  bottom up, base line first), `tabs` (short skill tab labels, 300's `ROLL_TABSKS_TAG` lines: `3s 3p 3c`) and
  `slash <a> <b>` (two skill tags as one, `ROLL_SLASH_<A>_<B>_TAG`: Arm of King Leoric's `3/3`). "Where" is judged per
  case at the highest rolls (the author's choice): base (its own and its cube upgrades), ethereal (an indestructible
  item never, an always-ethereal one, the item TSV's `eth`, always), sockets (none / its most), each corruption
  outcome (amulets also desecrated). `tools/label_cuts.py` runs the filter's rules (Main, every level) for every case
  with 045 as written without cut rules, simulates the steps and writes per item and step the BH condition (code, ETH,
  SOCK, STAT360, STAT206) to `tools/unique_cut_cases.tsv` (GENERATED); the generator puts it into 045 (a dropped
  roll: `!(...)` in that item's alias entry), then label_cuts measures every case again with that 045 and fails on a
  difference. It runs before the generator (hook, `build.bat`; CI: `--check`); `--report [NAME] [--all]` lists the
  longest labels, the conditions and what stays cut. A case it can't fix is reported "still cut".
  `BASE_RENAMES` in the generator (the author, 2026-10-19: `9qs` Holy Water Sprinkler shows as `Holy Sprinkler`): 045
  renames unidentified and non-magical items of the base (`!RW (!ID OR NMAG)`) and identified uniques and sets (their
  name line written again, by fingerprint), `sections/047-runeword-base-names.filter` (GENERATED by
  `gen_runeword_rolls.py`) the runewords; 210's Superior/Inferior trim skips them (`!RENAMED_BASES`, an alias 045
  writes). Identified magic, rare and crafted items keep the game's name (BH has no keyword for affix or rare names).
  One tag per stat when a roll and a corruption overlap (author's
  format, the rule): put the roll into the corruption line, `(STAT360=n OR ROLL_<X>_TAG)`. Only when that line's
  tag shows a second stat (e.g. `Ind 150ed`) or its slots mean another stat does a separate roll line
  skip the corruption instead (`!STAT360=n`). Two stats with the same look on one label are one tag too (the author,
  2026-10-19): Magic Find per level with Magic Find besides (Skullder's Ire corrupted +MF) shows the total at your
  level, `$f(MFIND+FLOOR(STAT240*CLVL/8))`; life per kill with life per demon kill (Odium corrupted +lpk) `5/15lpk`.
  Its aliases `ROLL_<X>_TAG` are wired into the tag lines of `300-affix-tags`; the slots each tag covers
  are listed in `COVER` in the generator and must match those lines. A fingerprint rules out each rival also as every
  corruption (on amulets, corruption and desecration) leaves it: `docs/pd2-corruptions.tsv` (CubeMain's outcomes in
  filter codes, `--extract`), so a corrupted Bloodtree Stump never reads as Bonesnap. A stat the item lacks
  (`SK134<1`) is the last resort; a corruption no stat tells apart is left out of the item's own tags
  (`!STAT360=47` on Skullder's Ire). `tabsk` counts one tag per skill tab the item has (300 has a line per tab).
- `sections/305-runeword-rolls.filter` is GENERATED by `tools/gen_runeword_rolls.py` from `docs/pd2-runewords.tsv`
  (PD2's Runes/Gems tables, one line per runeword and kind of base, written by the same `pd2_data.py --extract`) and
  `tools/runeword_roll_picks.txt` (one line per runeword; its versions share it). Never edit it by hand: edit the
  picks file and the hook regenerates. It holds its own aliases `RW_<X>_TAG` and tag lines (nothing in 300 to wire):
  each tag copies the look of the same stat's line in `300-affix-tags` (a skill or aura without one: the
  `310-staffmods` abbreviation in the 300 single-skill / aura look), so a 300 style edit restyles runewords on the
  next run, and its lines sit in the 300 stat-block order. A tag shows the item's total, roll plus runes (Doom's ED
  includes Ohm's): EDAM / EDEF, never ED (BH's ED leaves runeword bonuses out). Runewords take no corruption
  affixes (white bases corrupt only to sockets). BH can't name a runeword: each is told apart by `SOCK=n`, its slot
  and stats only it has among those runewords, never stats a white base can bring itself (superior, automagic such
  as a staff's FCR, staffmods) nor `DEF`. The label is three lines: name (gold), base line (`Eth Ghost Spear`: 220's
  Sup, Inf and superior `NNed` tags skip runewords, `!RW`, so names fit) and tags; the room assumes each version's
  longest elite base with `Eth `. A per-level roll (Enigma's `str/lvl`, `mf/lvl`) shows per level with a formula,
  `$f(STAT220/8)` = 0.75 (eighths, shifted by the stat's ValShift). All three -res rolls: one grouped tag as on Kira's
  Guardian, in the game's order (S14: fire, lightning, cold). A runeword's own shorter labels (Lionheart `25s 15d 20v`) are
  `SHORT_LABELS` in the generator; they get their own alias (`RW_STR_S_TAG`). Versions show only the picked rolls
  they have (Loyalty: power strike on spears, strafe on bows). The author picks in `pick_runewords.bat` (= `--picker`,
  the same page template, `tools/runeword_picker.html`; a card previews any of its bases, ethereal or not).
  A picked roll with no look yet (`*`) is a request (`--requests`): it needs a 300 line, and a new label needs the
  author's OK. Lint `rw-tag` flags a 300 tag line that can match a runeword.
- `sections/146-map-experience.filter` is GENERATED by `tools/gen_map_exp.py` from `docs/pd2-map-exp.tsv`: per map
  code an alias `MXR_<code>` (the roll multiplier: experience of a full clear with the map's rolls / without them;
  density, rarity, +XP %, +area level, Fortification, a guest monster) and a tag `1.7x`, one decimal cut off, in
  bands per tier (`BANDS`; the author asked for tier-relative bands and left the cuts to the data, 2026-10-16): the
  same percentiles of rolled rare maps (half corrupted) in every tier, no tag below the 10th, red from the 60th,
  purple from the 95th: gold / red / purple from T1 1.4x / 1.7x / 2.0x, T2 1.5 / 1.8 / 2.2, T3 1.6 / 2.0 / 2.5, T4
  2.3 / 2.6 / 3.0 (its rare maps; dungeons only come from the cube, a T3 map + Dungeon Scarab, whose recipe adds
  +40-50% experience and four monster mods to the six affixes: `recipe_mods` in `map_exp.py`); unique maps use the
  tier of their area level (87 T1, 88 T2, 89 T3). Identified maps only. The tag and the experience line are two
  description lines under 145's density / rarity highlights (the author's layout, tested in game 2026-10-18; BH
  draws description lines bottom up, so a later rule's line sits lower): the tag `2.0x Experience` in its band's
  colour, then the experience line, gold `2.6x at Level 98` (the viewer's level, `$f(CHARSTAT12)`). The experience
  line: a full clear of this map with its rolls
  for the viewer (level penalty per monster kind: normals, champions +2, uniques +3; their own +XP %,
  `CHARSTAT12`/`CHARSTAT85`) over the average white T1-T3 map for the same viewer (dungeons: the average white T3
  map; the author, 2026-10-17: at level 97 nobody weighs a dungeon against T1 maps), characters of level 80-98
  (`CLVL>79 CLVL<99`; maps need level 80); exact formulas, no shortcut (a tag x base x penalty shortcut is off by
  up to 100% at level 96-98). Alias `MXX_<code>`; the penalties (`MXPEN<level>_<k>`) and the averages (`MXAVG`,
  dungeons `MXT3AVG`: `BASELINES` in the generator) are aliases at the end of 146, used as `%NAME%` inside `MXX_`
  bodies: in output BH applies aliases in file order,
  so an alias may use a later one there (never in conditions); lint warns when such an alias comes first.
  `sections/147-map-display-end.filter` ends every map's display after it and holds the
  maps' closing minimap icons (145's T4 and unique-map looks continue into it). A band test sits inside the formula
  (`$f(ABS(2*t-35)<=3)` = 16 <= t <= 19, the long multiplier once): the repo's tools read a `$f(...)` island as one
  unknown word. Guest monsters ("Map contains ...", STAT437-442/470/471/499, one at most; T1-T3 affixes, Imperial
  Palace's fixed Fetishes): PD2 adds the guest to every area's monster list with weight 1, replacing nothing
  (S13 live and S14 beta alike; players believed it replaces a native), so a guest-capable map's
  coefficients are `IF(STAT<n>,...)` chains (BH reads any nonzero value as true); `docs/pd2-map-guests.tsv` holds
  each guest's exp per roll, the map TSV's `rarity` / `guests` columns the rest. The model (one line per map
  area: spawn rolls, reach, exp per normal / elite pack roll, MonUMin/Max, champions' share) comes from
  `map_exp.py "<Diablo II folder>"` (the model, kept out of the repo; rerun after a PD2 patch, then the generator): layouts (each DS1
  tile's variant picked by DT1 rarity, as the game does) and spawn
  rules (the base game's) with PD2's map stats applied as its area setup does; the spawn rule's
  closed form for elite packs, `--verify` checks it against the full simulation, `--ranges` rolls magic / rare /
  corrupted / unique maps (the author: T4 dungeons are always rare, never corrupted). Map item -> areas is `MAPS` in
  `map_exp.py` (the author:
  Zhar's Sanctum all three wings, Djinn's Domain's red map once, Outer Void three layouts + three random map
  bosses). The generator also has the personal multiplier (level penalty, `CHARSTAT12`/`CHARSTAT85`, guests too),
  not shown yet; `--selftest` evaluates the formulas' BH text against the Python model.
- `Erazure-Unique-Set-Tiers.html` (repo root, committed; the players' page, which GitHub Pages serves from `main`) is
  GENERATED by `tools/tier_map.py` from `tools/tier_map_template.html`. It runs every unique and set item
  (`docs/pd2-unique-set-items.tsv`, bases from `docs/pd2-bases.tsv`) through the filter's own rules at every filter
  level, Eth, character level, class, town / Discovery Progress state and variant, and shows each item's tier and

  counts the filter checks; `--findings` lists them (a tier rule on a base no such item drops as, a rule comment
  naming an item not on its base, a label BH cuts at 56 characters). Base names, types and quality levels, sound names
  (`Sounds.txt`) and the icon palette come from `python tools/pd2_data.py --tier-data "<Diablo II folder>"` (also
  run by `--extract`). An item line's columns (name, when, tier, label cell, icon and sound) are in px, not rem, so
  the icons line up on the website too (its theme sets a bigger root font). Sets have High and Medium tiers (`SET_HIGH_VALUE_*`, `SET_MEDIUM_VALUE_*`) and no Minimal:
  the author sees no room between Medium and the standard set look.
- `sections/205-white-runeword-bases.filter` holds the +skill runeword bases of white class items, one alias each
  (`RWB_PLAGUE_CLAW`, `RWB_DOMINION_WAND`...: codes, sockets and skills in one bracketed group). The tag rules of
  210/220, their hide rules' exceptions (`!(RWB_PLAGUE_CLAW OR RWB_CHAOS_CLAW OR RWB_MALICE_CLAW)`) and 310-staffmods'

- `Erazure-Non-Magic-Bases.html` (repo root, committed; the website's Non-magical Bases page shows it) is GENERATED by
  `tools/base_map.py` from `tools/base_map_template.html`: for every non-magical armor and weapon base, its tags and
  notifications, its own displays (`($)`, `[Imbue]`) and when it is hidden, per filter level (the Main version,
  outside town). One table per item type, the author's layout: Levels, Shows (Notify / Hidden pill, or the tag or
  display as the game draws it, the tag without the base name), Icon, Chat, Eth, Quality, ED, Sockets, Character
  level ("Above level 89", the rule's CLVL>89), then Class, Item level, All res, Skills, Other. Every table of a page
  has the page's columns at fixed widths (`table-layout: fixed`, a `<colgroup>`), so they line up from one item type
  to the next; a column a type never uses is blank there (the magic/rare pages do the same).
  Rows go Tag, Notify, Shows as, Hidden, each by first and last level, then non-eth before eth, nonsuperior before
  superior, then ED, sockets, character level. Bases of one type, tier, socket maximum and size with identical rows
  share a group (its header's sockets and size hold for each); low quality rows are a toggle. Every alias is
  expanded but the `RWB_` ones ("unless a Plague base"); a tag's named base
  is put inline, its shared parts in the columns and its skill combinations in a drop-down. An OR that mixes columns
  becomes one row per case (`(ED<19 OR SOCK=2)`: two rows). Each rule is folded per base (code, item groups, tier,
  most sockets, inventory size for `AREA`) and per level; a stopping rule loses the cases an earlier one with another
  outcome decides; a hide case another hide row covers is dropped. `--base 7wn,uit` prints bases' rows with their
  rules; `--findings` lists rules that apply to no base and minimap icons on items a rule hides (BH's notification
  pass ignores hiding). Sockets, size and skill names come from `--tier-data` (`docs/pd2-bases.tsv`,
  `docs/pd2-skills.tsv`). `build.bat`, the hook and CI run it as the tier page.
- `Erazure-Magic-Items.html` and `Erazure-Rare-Items.html` (repo root, committed; the website's Magic Items and Rare

  template, its `__MAP__` marker and scope class per page: `magic-map` / `rare-map`), on `base_map.py`'s engine
  (subclassed, not copied): every armor, weapon, quiver, ring, amulet, jewel and charm base as an unidentified

## Adding or splitting a section
- Name it `NNN-topic.filter` with a number between its neighbours (e.g. `115-...`). The build rejects other
  names, duplicate numbers, and any rule after the catch-all (`370-catch-all.filter` stays last).
- A split only moves lines between files: `--check` must still pass with the 8 filters unchanged.

## File format: preserve exactly
- Encoding: UTF-8 without BOM. Since PD2 Season 13, UTF-8 displays extended characters
  (•, ÿ, §, ¹²³) correctly. Do NOT convert to ANSI/Windows-1252, even though the wiki says to.
- Line endings: CRLF. Do not normalize to LF.
- `ÿc` + a character is an in-game color code (used in `ItemDisplayFilterName` lines). Never "fix" it.
- Many rules end with a trailing `//`. Match the style of the surrounding rules.
- Never reformat, re-indent, reorder, or "clean up" lines you were not asked to change.
  Diffs must be minimal: every stray change reaches players.

## Filter semantics
- Rule format: `ItemDisplay[conditions]: output`. Lines starting with `//` are ignored.
- Rules are evaluated TOP TO BOTTOM. The first matching rule WITHOUT `%CONTINUE%` decides the
  item's display and stops evaluation. Order is behavior.
- `%CONTINUE%` stores the rule's output into `%NAME%` and keeps evaluating. ~77% of rules are
  `%CONTINUE%` layers; later rules see the modified `%NAME%`.
- An empty output (`ItemDisplay[...]:` or output only inside `{}`) HIDES the item's name.
- Notification keywords (`%BORDER-xx%`, `%MAP-xx%`, `%DOT-xx%`, `%PX-xx%`, `%SOUNDID-n%`) are applied
  in a separate pass over only the rules that have one, so they fire even if an earlier rule stopped
  (or hid) the display. In that pass the FIRST matching rule alone decides the drop sound and the
  text notification, `%CONTINUE%` or not: a `%SOUNDID%` after an earlier matching notification rule
  never plays. Minimap icons stack until the first matching notification rule without `%CONTINUE%`.
- `%TIER-n%` limits the chat notification and drop sound to levels 0–n; the minimap icon still shows on every
  level (patch notes; the author uses `%TIER-0%` for icon-only items). BH reads one digit, so n is 0–9. Without it
  the notification fires at every level (so `%TIER-9%` is not the same: it skips levels 10–12).
- AND and OR have EQUAL precedence and are read left to right: `A OR B C` means `(A OR B) AND C`,
  not `A OR (B AND C)`. Bracket every OR group.
- Aliases (`Alias[X]:...`) are find-and-replace at load time, in definition order. In conditions the
  name is replaced wherever it occurs, even inside another word; in output only as `%X%`.
- Output keywords must be uppercase. An unknown `%word%` is shown as text. `%PERCENT%` shows a `%`.
- Limits (BH): a name shows 56 characters (512 for shop items), color codes not counted; 511 in all.
  Descriptions are cut with "..." past about 500 (less when the item's own text is long).
- `{}` = description text. `%CONTINUE%` only works outside braces.
- Item groups (BH `Item.cpp`): a weapon is in one weapon group, the first of club, mace, hammer, wand, staff, bow,
  axe, scepter, sword, dagger, javelin, spear, polearm, crossbow its item types include. So javelins (Amazon ones
  too) are `JAV`, never `SPEAR`, though PD2's item types make them spears (runewords for spears take them);
  Amazon spears are `SPEAR`. `MACE` is clubs, maces and hammers (`TMACE` the maces alone). Circlets are `CIRC`,
  never `HELM`. The pages' generators follow this (`item_groups` in `tools/tier_map.py`).
- The game's Loot Filter options (BH c37b344 and PRs #107-#109, 2026-10-18; the filter can't read them): Hide
  Healing Potions / Hide Mana Potions (default off) hide every `hp1`-`hp5` / `mp1`-`mp5` before any rule, on every
  level, even level 0 (rejuvenation and utility potions stay the filter's); the name is emptied everywhere (shops,
  inventory, belt, stash too). BH's minimap pass skips every item BH made invisible (#108): no icon, no chat line.
  Force Show Undiscovered (default ON) / Unowned (default off): BH runs the filter first (#107); only a unique or
  set the filter hides that is not all-discovered / all-owned is shown anyway, with BH's own name (the game's,
  plus BH's item level / socket options). `GRAIL_NEW` (040) never hides undiscovered items, so they keep the
  filter's looks with the option on or off.
- The last rule is the catch-all `ItemDisplay[]:%NAME%{%NAME%}//`. Nothing goes after it.

## Before adding or changing a rule
1. Search `sections/` for every rule touching the same item code / group / stat
   (e.g. `r30`, `RUNE>29`, `STAT127`, `amu`). List them with file and line.
2. Decide where the new rule must sit relative to those rules. Explain:
   - which earlier non-CONTINUE rules could stop it from ever being reached (shadowing),
   - which later rules it will now shadow,
   - which `%CONTINUE%` layers before it will already have modified `%NAME%`.
3. State the affected FILTLVL levels explicitly (e.g. "levels 8–12 only").
4. Check whether BIG_GG / REVEALED / POE_SOUNDS variants need different behavior.
5. Only then edit, in the section file where that rule belongs.
